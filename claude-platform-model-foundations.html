Claude Platform & Model Foundations

For recurring work, team projects, and deliverables that need to hold up under review, the feature decisions made inside Claude before writing a single prompt set the quality ceiling for everything the session produces.

This module builds the framework for the four decisions that sit at the front of every Claude interaction: which entry point to use, which capability features to activate, which model to select, and how to manage context across a session. These four decisions determine whether sessions build on prior work or require constant re-setup.

01 How Claude
behaves

How Claude behaves

Before selecting entry points and models, five behavioural properties apply to Claude regardless of which feature you use. Understanding them prevents the most common sources of frustration and misaligned expectations.

  • Responses vary

    Ask Claude the same question twice and you will get two different answers. Both may be useful, but neither should be viewed as the "one correct response." This is how generative AI works: outputs are produced using probability, not retrieved from a fixed database. Plan for variation in any workflow that depends on consistent outputs, and build review into the process.

  • Confident tone is not a signal of accuracy

    Claude writes with consistent fluency regardless of whether the answer is actually correct. A fabricated statistic reads with the same assurance as a verified one. Module 3 builds verification habits; without them, fluency signals nothing about accuracy.

  • Context is a budget

    Every Claude conversation holds a working-memory limit. As a conversation approaches its limit, claude.ai automatically summarises earlier messages so the session can continue (on paid plans with Code Execution enabled). Summaries compress detail, which is why instructions followed at the start of a two-hour session can lose force by the end.

  • Knowledge has a training boundary

    Claude's training data has a cutoff date. Information after that date is outside Claude's reliable knowledge unless you connect a current source, turn on web search in chat, or use Research. This affects recent events, current regulations, and up-to-date market data. When relevance matters, verify or connect a source.

  • Configured procedures still produce varied outputs

    A Skill set up to run the same procedure every time reduces output variance but does not eliminate it. Even a well-configured workflow produces different outputs each time it runs. Configuration reduces variation; it does not remove the need to check the output.

Ako sa Claude chová

Ešte pred výberom vstupného bodu a modelu platí päť vlastností chovania, ktoré sa vzťahujú na Claude bez ohľadu na to, ktorú funkciu použijete. Ich pochopenie predchádza najčastejším zdrojom frustrácie a nerealistických očakávaní.

  • Odpovede sa líšia

    Ak sa Claude spýtate tú istú otázku dvakrát, dostanete dve odlišné odpovede. Obe môžu byť užitočné, ale ani jednu netreba považovať za „jedinú správnu". Tak funguje generatívna AI: výstupy vznikajú na základe pravdepodobnosti, nie sú načítané z pevnej databázy. V každom postupe, ktorý závisí od konzistentných výstupov, počítajte s rozptylom a zahrňte doň kontrolu.

  • Presvedčivý tón nie je znakom správnosti

    Claude píše rovnako plynulo bez ohľadu na to, či je odpoveď skutočne správna. Vymyslený štatistický údaj sa číta s rovnakou istotou ako overený. Modul 3 buduje návyky na overovanie; bez nich plynulosť nehovorí o správnosti nič.

  • Kontext je rozpočet

    Každá konverzácia s Claude má limit pracovnej pamäti. Keď sa konverzácia k limitu blíži, claude.ai automaticky sumarizuje starší priebeh, aby mohla session pokračovať (na platených plánoch so zapnutým Code Execution). Sumarizácia stláča detail, a preto pokyny, ktoré Claude na začiatku dvojhodinovej session dodržiaval, môžu ku koncu stratiť silu.

  • Znalosti majú hranicu tréningu

    Tréningové dáta Claude majú dátum uzávierky. Informácie po tomto dátume ležia mimo spoľahlivých znalostí Claude, pokiaľ nepripojíte aktuálny zdroj, nezapnete v chate vyhľadávanie na webe alebo nepoužijete Research. Týka sa to nedávnych udalostí, aktuálnej regulácie a čerstvých trhových dát. Ak záleží na aktuálnosti, overte alebo pripojte zdroj.

  • Aj nakonfigurovaný postup dáva rôzne výstupy

    Skill nastavený na rovnaký postup pri každom spustení rozptyl výstupov znižuje, ale neodstraňuje. Aj dobre nastavený workflow vyprodukuje pri každom spustení iný výstup. Konfigurácia rozptyl zmenšuje; potrebu skontrolovať výstup neruší.

02 Core entry
points

Core entry points

Claude appears in one interface, but that interface offers four distinct working entry points: Chat, Projects, Artifacts, and Research. Choosing the right one before starting work determines how efficiently the session runs and whether the context you build today carries forward to tomorrow.

Chat
The default entry point: an unstructured conversation. A Chat is saved to your history and can be continued later, and Memory plus past-chat search can carry key context into new sessions. What Chat does not give you is a Project's deliberate persistence — standing instructions and a curated knowledge base.
Use Chat for one-off questions, quick drafts, exploratory prompting, and tasks you will not repeat. It works well for any task that starts and ends in that session. When you find yourself opening a new Chat by pasting the same background paragraph you pasted last week, that workstream has outgrown Chat.
Projects
Persistent workspaces. A Project holds three things:
  • Standing instructions — what Claude should know and do consistently across every conversation in this space.
  • Knowledge base — documents, policies, and reference files uploaded once so Claude can draw on them without re-uploading each session.
  • Conversation history — each Project maintains its own conversation list, separate from your global history. Conversations inside a Project share the Project's instructions and knowledge base, but they do not share context with each other.
Projects solve the most common productivity drain in AI-assisted professional work: re-explaining the same background every session. Set the context once, and every conversation that follows starts with it already in place.
Artifacts
The right output format when the result is a deliverable rather than a conversational reply. When Claude produces an Artifact, it appears as a separate, editable block alongside the chat rather than flowing into the thread. Use Artifacts for draft documents, data tables, formatted reports, and code. Use inline responses for answers you will act on within the conversation.
Research
Deep multi-source synthesis (available on paid plans). Regular Chat can search the web: web search is available on all Claude plans as a per-chat toggle in the chat input. On Team and Enterprise plans, an Owner or Primary Owner must first enable web search for the workspace in the organisation's capability settings before members can switch it on. Official documentation does not specify whether the toggle is on or off by default.
Research goes further: it runs multi-step searches across multiple sources and synthesises them. Use Research when the task needs deep investigation across a range of sources, or synthesis of current information beyond a quick lookup.

A worked comparison

Wrong entry point

The same setup, every week

A project coordinator drafts weekly team status reports. Every Monday she opens a new Chat and types the same opener: project name, team structure, stakeholder list, report format requirements, and last week's open items. Claude produces a good report — but the session takes 40 minutes, about 12 of which are context-loading.

40 min · 12 min of setup

Right entry point

Set up once, benefit every session

She builds a Project. Project background, team structure, and stakeholder list go into the knowledge base. Report format and standing instructions about escalation thresholds go into the Project instructions. On Monday she opens the Project and pastes the week's updates. The context is already there.

25 min · 0 min of setup

The report quality is the same. The entry-point decision eliminated the weekly setup tax.

The test for whether a Project is worth building

  1. Does this task recur?
  2. Is the background context the same across sessions?
  3. Is the output format consistent?

If the answer is yes to two or more, build the Project. The setup time is recovered within two or three sessions.

Hlavné vstupné body

Claude sa javí ako jedno rozhranie, no ponúka štyri odlišné pracovné vstupné body: Chat, Projects, Artifacts a Research. Voľba správneho vstupného bodu ešte pred začiatkom práce určuje, ako efektívne session prebehne a či sa kontext, ktorý dnes vytvoríte, prenesie aj na zajtra.

Chat
Predvolený vstupný bod: neštruktúrovaná konverzácia. Chat sa ukladá do histórie a môžete v ňom neskôr pokračovať; Memory spolu s vyhľadávaním v starších chatoch dokáže preniesť kľúčový kontext do nových sessions. Čo Chat neposkytuje, je zámerná trvalosť Projektu — teda trvalé pokyny a kurátorovaná znalostná báza.
Chat používajte na jednorazové otázky, rýchle koncepty, prieskumné promptovanie a úlohy, ktoré nebudete opakovať. Funguje dobre pre všetko, čo začne a skončí v tej istej session. Keď však zistíte, že v novom Chate znova vkladáte ten istý odstavec s pozadím ako minulý týždeň, tento pracovný tok už Chatu odrástol.
Projects
Trvalé pracovné priestory. Projekt obsahuje tri veci:
  • Trvalé pokyny — čo má Claude konzistentne vedieť a robiť v každej konverzácii v tomto priestore.
  • Znalostná báza — dokumenty, smernice a referenčné súbory nahraté raz, aby z nich Claude mohol čerpať bez opakovaného nahrávania v každej session.
  • História konverzácií — každý Projekt má vlastný zoznam konverzácií, oddelený od globálnej histórie. Konverzácie v Projekte zdieľajú jeho pokyny a znalostnú bázu, ale kontext medzi sebou nezdieľajú.
Projekty riešia najčastejší zdroj straty produktivity v práci s AI: opakované vysvetľovanie toho istého pozadia v každej session. Kontext nastavíte raz a každá nasledujúca konverzácia ním už začína.
Artifacts
Správny formát výstupu vtedy, keď je výsledkom hotový dokument, nie konverzačná odpoveď. Keď Claude vytvorí Artifact, zobrazí sa ako samostatný, editovateľný blok vedľa chatu, nie ako súčasť vlákna. Artifacts používajte na koncepty dokumentov, tabuľky s dátami, formátované reporty a kód. Odpovede priamo vo vlákne používajte na to, s čím budete pracovať v rámci konverzácie.
Research
Hĺbková syntéza z viacerých zdrojov (dostupné na platených plánoch). Bežný Chat vie vyhľadávať na webe: vyhľadávanie na webe je dostupné na všetkých plánoch Claude ako prepínač pre jednotlivý chat v poli na zadávanie. Na plánoch Team a Enterprise musí Owner alebo Primary Owner najprv povoliť vyhľadávanie na webe pre celý workspace v nastaveniach schopností organizácie, až potom si ho členovia môžu zapnúť. Oficiálna dokumentácia neuvádza, či je prepínač predvolene zapnutý alebo vypnutý.
Research ide ďalej: spúšťa viackrokové vyhľadávanie vo viacerých zdrojoch a syntetizuje ich. Použite ho vtedy, keď úloha vyžaduje hĺbkový prieskum v širšom spektre zdrojov alebo syntézu aktuálnych informácií nad rámec rýchleho dohľadania.

03 Capability
layer

Capability layer

Entry points determine where you work. The capability layer determines what Claude can do within that entry point.

Three features extend Claude's default text-generation behaviour in ways that matter for professional work: Skills for consistent procedures, Code Execution for verified computation, and Memory for continuity across sessions.

The four-layer model

The layers are independent. Use any combination based on what the task requires. A one-off question needs none of them; a recurring analytical workflow might use all four.

LayerWhat it holds
Projectscarry context — what background knowledge and standing instructions apply to this workstream.
Skillsdefine procedures — how a specific task should be executed, consistently, every time.
Code Executionverifies computations — when the result must be correct, not merely plausible.
Memorypersists continuity — relevant facts carry forward across sessions without re-entry.
Skills
Reusable procedures. Anthropic provides built-in Skills for common professional tasks: creating, editing, and analysing Excel spreadsheets, Word documents, PowerPoint decks, and PDFs. Custom Skills can be added via settings for task-specific workflows. Skills live at the account level, not inside any one Project, and Claude invokes them automatically when relevant in any conversation, inside or outside a Project.
A Project's own configuration is its standing instructions and knowledge base; an active Skill tells Claude to follow a defined procedure for that task type, consistently, wherever it applies.
Two things to keep in mind. First, Skills reduce variance but do not eliminate it — a Skill that generates weekly reports in a consistent format will still produce different prose each run, so review stays in your workflow. Second, Skills require a trust evaluation: a Skill has access to whatever you give Claude access to during the session. Before enabling a third-party Skill, review its source and the permissions it requests. Anthropic-provided Skills and Skills approved by your organisation are the lower-risk starting point. Module 6 covers this evaluation in full.
Code Execution
Claude's sandboxed computation environment. Claude writes and runs code internally, then returns the result. You do not write the code yourself.
Why the distinction matters. Claude generates prose by producing the most probable next sequence of text. That works well for language tasks. For computation, it produces plausible-looking numbers that may or may not be accurate. Code Execution produces a verified result by running the calculation.
Use Code Execution instead of asking Claude to calculate when:
  • Any numeric output will be used or reported (calculations, projections, summaries of figures).
  • Data needs to be transformed or cleaned (date normalisation, deduplication, field formatting).
  • The output needs to be a chart or visualisation.
  • The output needs to be a real downloadable file (.xlsx, .pptx, .docx, .pdf).
Memory
Memory retains work-relevant facts across sessions, removing the need to re-enter the same context each time. Professionals typically store recurring role context, preferences for output format, names of frequent collaborators, and standing constraints that apply across projects.
Curation. Memory is most useful when actively curated. A memory that was accurate last quarter and has not been reviewed since can be actively misleading. Review stored memories periodically — at least monthly for active users; delete or update entries that no longer hold; keep the stored set focused on information that genuinely recurs.
Project-scoped Memory keeps Memory contexts separate for each Project, so context from client A does not appear in client B sessions. Set up separate Projects for separate workstreams and Memory will follow the same boundaries.
Incognito mode keeps a session out of Memory and chat history (it applies to standalone chats, outside Projects). Use it for sensitive conversations or exploratory work with confidential inputs. It does not override your organisation's underlying data retention.

Verify at delivery. Importing memories from other AI platforms is an experimental feature as of June 2026. Memory import is documented for Free, Pro, Max, and Team plans (not Enterprise). If the automatic import path is not available in your account, the documented fallback is to add the key facts to Memory manually through memory settings — not to route them into a Project's knowledge base.

Scenario · a monthly report that got faster and more accurate at once

Illustrative scenario.

A business analyst produced a regulatory tracking report once a month. The task was consistent: take that month's regulatory updates, identify which applied to the portfolio, summarise the implications, and format the output per a defined template. High stakes, repeatable structure.

For the first two months she ran the workflow in Chat. Each session she uploaded the regulatory documents, re-pasted the portfolio context, and re-typed the format instructions. She ran a verification step on every numeric figure, catching two errors in month one and one in month two — all before the report went out.

In month three she rebuilt the workflow using the capability layer. Portfolio context and standing format instructions went into the Project, prior reports into the knowledge base, a Skill handled the report output format, and numeric calculations moved to Code Execution.

Time per session dropped from 65 minutes to 30, and the verification step still ran. No errors were found in months three through eight.

Checkpoint

A recurring contract review workflow has five components. For each one, decide which capability layer it belongs in — standing instructions, knowledge base, Skill, or Code Execution. Each layer is used at least once.

  • The company's standard contract playbook (acceptable terms, required clauses, risk thresholds).
  • The contract documents for this review cycle, uploaded at the start of each session.
  • The instruction: "Flag any clause that departs from the playbook and explain the departure in one sentence."
  • A procedure that extracts flagged clauses and formats them into the company's standard review report template.
  • A calculation of the financial exposure from a penalty clause with a variable rate structure.

Vrstva schopností

Vstupné body určujú, kde pracujete. Vrstva schopností určuje, čo Claude v rámci daného vstupného bodu dokáže.

Tri funkcie rozširujú predvolené generovanie textu spôsobmi, ktoré sú pre profesionálnu prácu podstatné: Skills pre konzistentné postupy, Code Execution pre overený výpočet a Memory pre kontinuitu medzi sessions.

Model štyroch vrstiev

Vrstvy sú nezávislé. Použite ktorúkoľvek kombináciu podľa toho, čo úloha vyžaduje. Jednorazová otázka nepotrebuje ani jednu; opakujúci sa analytický workflow môže využiť všetky štyri.

VrstvaČo nesie
Projectsnesú kontext — aké znalosti o pozadí a trvalé pokyny platia pre tento pracovný tok.
Skillsdefinujú postupy — ako sa má konkrétna úloha vykonať, konzistentne, každý raz.
Code Executionoveruje výpočty — keď musí byť výsledok správny, nie len vierohodný.
Memoryudržiava kontinuitu — relevantné fakty sa prenášajú medzi sessions bez opätovného zadávania.
Skills
Opakovane použiteľné postupy. Anthropic poskytuje vstavané Skills pre bežné pracovné úlohy: tvorbu, editáciu a analýzu tabuliek Excel, dokumentov Word, prezentácií PowerPoint a PDF. Vlastné Skills sa pridávajú v nastaveniach pre špecifické workflowy. Skills existujú na úrovni účtu, nie vnútri jedného Projektu, a Claude ich vyvolá automaticky, keď sú relevantné — v akejkoľvek konverzácii, v Projekte aj mimo neho.
Vlastnou konfiguráciou Projektu sú jeho trvalé pokyny a znalostná báza; aktívny Skill hovorí Claude, aby pre daný typ úlohy konzistentne dodržal definovaný postup, kdekoľvek sa uplatní.
Dve veci majte na pamäti. Prvá: Skills rozptyl znižujú, ale neodstraňujú — Skill generujúci týždenné reporty v konzistentnom formáte vytvorí pri každom spustení iný text, takže kontrola vo workflowe zostáva. Druhá: Skills si vyžadujú vyhodnotenie dôveryhodnosti — Skill má prístup ku všetkému, k čomu počas session dáte prístup Claude. Pred zapnutím Skillu tretej strany si preverte jeho zdroj a oprávnenia, ktoré požaduje. Skills od Anthropic a Skills schválené vašou organizáciou sú štartovacím bodom s nižším rizikom. Modul 6 sa tomuto vyhodnoteniu venuje v plnom rozsahu.
Code Execution
Izolované (sandboxované) výpočtové prostredie Claude. Claude interne napíše a spustí kód a potom vráti výsledok. Kód nepíšete vy.
Prečo je tento rozdiel podstatný. Claude tvorí text tak, že produkuje najpravdepodobnejšie pokračovanie. Pri jazykových úlohách to funguje dobre. Pri výpočtoch to produkuje vierohodne vyzerajúce čísla, ktoré správne byť môžu aj nemusia. Code Execution dá overený výsledok tým, že výpočet skutočne vykoná.
Code Execution použite namiesto toho, aby ste Claude nechali počítať, keď:
  • sa akýkoľvek číselný výstup bude používať alebo reportovať (výpočty, projekcie, súhrny údajov);
  • treba dáta transformovať alebo vyčistiť (normalizácia dátumov, deduplikácia, formátovanie polí);
  • výstupom má byť graf alebo vizualizácia;
  • výstupom má byť skutočný súbor na stiahnutie (.xlsx, .pptx, .docx, .pdf).
Memory
Memory uchováva pracovne relevantné fakty medzi sessions, takže netreba zadávať ten istý kontext znova. Profesionáli si tam typicky ukladajú opakujúci sa kontext svojej role, preferencie formátu výstupov, menách častých spolupracovníkov a trvalé obmedzenia platné vo viacerých projektoch.
Kurácia. Memory je najužitočnejšia, keď ju aktívne spravujete. Záznam, ktorý bol správny minulý kvartál a odvtedy ho nikto neprešiel, môže aktívne zavádzať. Uložené záznamy pravidelne prechádzajte — pri aktívnych používateľoch aspoň raz mesačne; mažte alebo aktualizujte to, čo už neplatí; udržujte uloženú sadu zameranú na informácie, ktoré sa skutočne opakujú.

04 Choosing
models

Choosing models

The capability layer determines what Claude does. The model determines how well Claude does it, and at what cost in speed.

Different model tiers in the Claude family span a range from efficient-and-fast to thorough-and-capable. Matching the tier to the task avoids both over-engineering routine work and under-resourcing high-stakes analysis.

Haiku

The fastest and most efficient model in the family. It handles structured tasks well: classification, extraction, formatting, straightforward summarisation, and high-volume routine work where speed matters and the cost of an imperfect output is low. Across hundreds of items in sequence, Haiku's speed advantage compounds.

Speed
Depth

Sonnet

The balanced tier. It handles the full range of professional tasks with strong quality: drafting, synthesis, analysis, research assistance, and document review. For most knowledge work, Sonnet is the right starting point. If quality falls short on a complex task, upgrade to Opus; if speed and volume dominate and the task is structured, consider Haiku.

Speed
Depth

Opus

A higher-capability tier with more advanced performance than Sonnet and Haiku. Use it for nuanced judgment, complex multi-step reasoning, ambiguous inputs that require interpretation, or any work where quality outranks speed. Client-facing deliverables, complex document analysis, strategic planning, and high-stakes multi-source synthesis are typical candidates.

Speed
Depth

Gauges show relative positioning described in this module, not benchmark data.

Decision logic

Task profileModel
Routine, structured extraction or classification at volumeHaiku
Most professional drafting, synthesis, and analysisSonnet
Complex judgment, high-stakes output, ambiguous or multi-layered inputsOpus

On usage and cost

Opus produces better output on complex tasks, with the tradeoff of running slower. For most knowledge work Sonnet handles the task well; reserve Opus for work where the quality ceiling genuinely matters, and use Haiku where volume and speed are the primary requirements and the task has clear structure.

One additional dimension: on metered or usage-budgeted plans (including API access), the speed-versus-capability trade-off also becomes a per-call cost trade-off. A higher-capability tier such as Opus consumes more usage per call than Haiku or Sonnet, so on those plans "efficiency" means cost as well as speed. On the standard claude.ai subscription surface, treat efficiency — speed and usage headroom — as the practical proxy for cost. The selection logic above does not change.

Verify at delivery. The model picker lineup, the default model, and automatic model-switching behaviour vary by plan and change over time; verify all three in the product. As of June 2026 the shipped model family includes a fourth tier above Opus (Claude Fable 5, GA 2026-06-09), and Opus-tier latency is currently characterised as moderate rather than slow. The certification pins the three-tier Haiku/Sonnet/Opus frame, so this lesson teaches that frame — tier names and characteristics are a verify-at-delivery item, not exam-relevant. The decision logic applies regardless of which tiers are available to you.

Výber modelu

Vrstva schopností určuje, čo Claude robí. Model určuje, ako dobre to robí — a za akú cenu v rýchlosti.

Jednotlivé triedy modelov v rodine Claude pokrývajú rozsah od efektívnych a rýchlych až po dôkladné a vysoko schopné. Priradenie správnej triedy k úlohe zabráni tak zbytočnému predimenzovaniu rutinnej práce, ako aj poddimenzovaniu analýzy s vysokým rizikom.

Haiku

Najrýchlejší a najefektívnejší model v rodine. Dobre zvláda štruktúrované úlohy: klasifikáciu, extrakciu, formátovanie, priamočiaru sumarizáciu a rutinnú prácu vo veľkých objemoch, kde záleží na rýchlosti a cena nedokonalého výstupu je nízka. Pri stovkách položiek za sebou sa rýchlostná výhoda Haiku kumuluje.

Na štandardnom predplatnom povrchu claude.ai berte efektivitu — rýchlosť a rezervu v spotrebe — ako praktický zástupný ukazovateľ nákladov. Logika výberu uvedená vyššie sa nemení.

Logika rozhodovania platí bez ohľadu na to, ktoré triedy máte k dispozícii.

05 Context
management

Context management

Model selection and capability configuration determine what Claude can do in a session. Context management determines how long it can do it well. Every conversation has a finite working-memory budget, and that budget runs down as the conversation grows.

The context window in practical terms

As messages and uploaded documents accumulate, Claude's context window fills. As it fills toward the limit, claude.ai automatically summarises earlier messages to make room (on paid plans with Code Execution enabled), and the full history remains available for reference. In practical terms: a long session where you gave Claude detailed instructions in the first 10 minutes may produce responses 90 minutes later that don't follow those instructions — not because Claude is ignoring them, but because detail can compress when earlier context is summarised.

Signs a conversation needs intervention

  • Claude stops following instructions it followed correctly earlier in the same session.
  • Responses address only the most recent exchange, without reference to earlier decisions or context.
  • Accuracy drops in ways consistent with missing early-session context.

Three responses when context degrades

Restart
Start a new conversation. The Project's standing instructions and knowledge base carry forward automatically; the conversation thread does not. Restarting is the right call when the current session has drifted beyond recovery, or when you are beginning a genuinely new task within the same workstream.
Summarise
Before starting a new conversation, ask Claude to produce a summary of the current state: decisions made, work in progress, and open questions. Paste that summary at the start of the new conversation as context. This preserves thread continuity without carrying a degraded context window forward.
Persist
For information that should be available across all future sessions, save it to Memory or update the Project knowledge base. Saving the right information at the right moment is more efficient than re-entering it repeatedly. A well-maintained Project with current knowledge base entries reduces the impact of individual session context limits.

Memory curation

Memory serves best when it stays current. An entry that was accurate three months ago and has not been reviewed since can be actively misleading. Treat Memory like a working file: review it on a regular cadence, delete entries that have expired, and update facts that have changed. The accuracy of stored memories matters more than the volume.

Usage limits

Claude's usage limits operate on more than one time window: a short rolling session window, plus weekly limits on paid plans that apply across models, with a separate weekly pool for the highest model tier. Extended sessions on higher-tier models may reach a limit before the work is complete. For intensive tasks, planning ahead is more efficient than working around an interrupted session: break large tasks into segments, save interim progress to the knowledge base, and restart from a summary rather than extending a single session indefinitely.

Verify at delivery. The specific windows and allowances vary by plan and change over time; verify current limits in the Help Center.

Práca s kontextom

Výber modelu a konfigurácia schopností určujú, čo Claude v session dokáže. Práca s kontextom určuje, ako dlho to dokáže robiť dobre. Každá konverzácia má obmedzený rozpočet pracovnej pamäti a ten sa s rastúcou konverzáciou vyčerpáva.

Kontextové okno v praxi

Ako sa kopia správy a nahraté dokumenty, kontextové okno Claude sa plní. Keď sa blíži k limitu, claude.ai automaticky sumarizuje starší priebeh, aby uvolnil miesto (na platených plánoch so zapnutým Code Execution), pričom celá história zostáva dostupná na dohľadanie. V praxi to znamená: v dlhej session, kde ste Claude dali detailné pokyny v prvých 10 minútach, môžu odpovede po 90 minútach tieto pokyny nedodržiavať — nie preto, že by ich Claude ignoroval, ale preto, že detail sa pri sumarizácii staršieho kontextu stláča.

Signály, že konverzácia potrebuje zásah

  • Claude prestane dodržiavať pokyny, ktoré v tej istej session skôr dodržiaval správne.
  • Odpovede reagujú len na poslednú výmenu bez odkazu na skoršie rozhodnutia či kontext.
  • Presnosť klesá spôsobom, ktorý odpovedá chýbajúcemu kontextu zo začiatku session.

Tri reakcie, keď kontext degraduje

Restart
Začnite novú konverzáciu. Trvalé pokyny a znalostná báza Projektu sa prenesú automaticky; vlákno konverzácie nie. Restart je správnou voľbou vtedy, keď sa aktuálna session odchýlila natoľko, že sa už nedá zachrániť, alebo keď v tom istom pracovnom toku začínate skutočne novú úlohu.
Sumarizácia
Pred začatím novej konverzácie požiadajte Claude o súhrn aktuálneho stavu: prijaté rozhodnutia, rozpracovanú prácu a otvorené otázky. Tento súhrn vložte na začiatok novej konverzácie ako kontext. Zachová sa tým kontinuita vlákna bez toho, aby ste si do ďalšej session preniesli degradované kontextové okno.
Uloženie
Informácie, ktoré majú byť dostupné vo všetkých budúcich sessions, uložte do Memory alebo aktualizujte znalostnú bázu Projektu. Uložiť správnu informáciu v správnom momente je efektívnejšie než ju opakovane zadávať. Dobre udržiavaný Projekt s aktuálnou znalostnou bázou znižuje dopad limitov kontextu jednotlivých sessions.

Kurácia pamäti

Memory slúži najlepšie, keď je aktuálna. Záznam, ktorý bol správny pred troma mesiacmi a odvtedy ho nikto neprešiel, môže aktívne zavádzať. Berte Memory ako pracovný súbor: prechádzajte ju v pravidelnej kadencii, mažte záznamy, ktorým vypršala platnosť, a aktualizujte fakty, ktoré sa zmenili. Na presnosti uložených záznamov záleží viac než na ich množstve.

Limity používania

Limity používania Claude fungujú vo viac než jednom časovom okne: krátke klzavé okno pre session plus týždenné limity na platených plánoch, ktoré platia pre modely spoločne, s oddeleným týždenným objemom pre najvyššiu triedu modelu. Dlhšie sessions na vyšších triedach modelov môžu dosiahnuť limit ešte pred dokončením práce. Pri náročných úlohách je plánovanie dopredu efektívnejšie než obchádzanie prerušenej session: rozdeľte veľké úlohy na časti, priebežný postup ukladajte do znalostnej bázy a namiesto nekonečného predlžovania jednej session začnite znova zo súhrnu.

Overiť pri publikovaní. Konkrétne okná a objemy sa líšia podľa plánu a v čase sa menia; aktuálne limity si overte v Help Center.

Časť 2 · obhájte jednu konfiguráciu

Priradenie scenára ku karte ukazuje, že správnu konfiguráciu rozpoznáte. Tento krok žiada, aby ste jednu obhájili. Vezmite S3 — 15-stranovú analýzu pre správnu radu zo štyroch nahratých reportov. Uveďte model, ktorý by ste vybrali, a jednou vetou kompromis: čo vám voľba prináša a čo vás stojí. Potom si zobrazte vzorovú odpoveď a porovnajte svoje zdôvodnenie, nie len výber.

Vaša zaznamenaná odpoveď. Opus. S Opusom dostaneme hĺbkovú analýzu a jemnú interpretáciu. Opus nás bude stáť vyššiu latenciu — nižšiu rýchlosť — a vyššiu spotrebu tokenov.

Vzorová odpoveď

Opus. Analýza pre správnu radu stojí na jemnej interpretácii nejednoznačných signálov zo štyroch zdrojov, takže kvalitatívny strop je dôležitejší než čas dodania. Opus prináša hĺbku uvažovania za cenu rýchlosti a pri jednorazovom výstupe s vysokým rizikom sa tento kompromis vyplatí. Sonnet by bol správnou voľbou, keby bola tá istá analýza rutinná alebo časovo kritická namiesto rizikovej; Haiku by interpretáciu, ktorú úloha vyžaduje, poddimenzoval.

Vlastné porovnanie

  • Voľba — vybrali ste Opus? Je to trieda pre hĺbkovú analýzu, jemnú interpretáciu a dlhé výstupy s vysokým rizikom.
  • Čo vám to prináša — spomenuli ste schopnosť uvažovania, jemnú interpretáciu alebo hĺbkovú syntézu? Nejednoznačné signály plus 15-stranová analýza robia z hĺbky hlavný faktor.
  • Čo vás to stojí — spomenuli ste vyššiu latenciu a vyššiu spotrebu na volanie? To je jadro kompromisu pri voľbe Opusu.

Podstatné je, či vaša jedna veta pomenovala kompromis, ktorý ste robili — nie to, ktoré písmeno ste vybrali.

Kvíz · výber platformy a modelu

Q1

An operations analyst runs a weekly inventory reconciliation. Each week she uploads a new inventory file, compares it against a reorder threshold document that has not changed in a year, and produces a formatted exception report. Which configuration best fits this workflow?

  1. A new Chat conversation each week, with the threshold document and inventory file pasted in
  2. A Project with the threshold document in the knowledge base, standing instructions for the exception format, and Code Execution for the comparison calculations
  3. Research with the inventory file uploaded each week
  4. Artifacts saved from each week's session as the primary continuity mechanism

Why B. This is a recurring, structured workflow. Storing the static threshold document in a Project knowledge base and setting the exception format as standing instructions avoids re-uploading the same context weekly. Code Execution is required to guarantee accurate comparison of inventory numbers.

Operačná analytička robí týždenné zladenie skladových zásob. Každý týždeň nahrá nový súbor so zásobami, porovná ho s dokumentom hraníc pre doobjednanie, ktorý sa rok nezmenil, a vytvorí naformátovaný report výnimiek. Ktorá konfigurácia tomuto workflowu najlepšie sedí?

  1. Každý týždeň nová konverzácia v Chate, s vloženým dokumentom hraníc aj súborom zásob
  2. Projekt s dokumentom hraníc v znalostnej báze, trvalými pokynmi pre formát výnimiek a Code Execution pre porovnávacie výpočty
  3. Research so súborom zásob nahratým každý týždeň
  4. Artifacts uložené z každej týždennej session ako hlavný mechanizmus kontinuity

Prečo B. Ide o opakujúci sa štruktúrovaný workflow. Uloženie statického dokumentu hraníc do znalostnej bázy Projektu a nastavenie formátu výnimiek ako trvalých pokynov odstráni týždenné nahrávanie toho istého kontextu. Code Execution je potrebný na zaručenie presného porovnania skladových čísel.

Q2

A financial planner asks Claude to calculate compound interest on a portfolio scenario with five input variables. Which approach produces the most trustworthy result?

  1. Asking Claude to calculate it in a Chat conversation and reviewing the answer manually
  2. Uploading the variables to a Project and asking Claude to estimate the figure
  3. Using Code Execution to run the calculation and return a verified result
  4. Using Research to find comparable portfolio scenarios from public sources

Why C. Generating numbers as text can produce arithmetic mistakes. Code Execution makes Claude write and run the compound-interest calculation as code, producing an exact, verified result.

Finančný poradca požiada Claude o výpočet zloženého úročenia pre portfóliový scenár s piatimi vstupnými premennými. Ktorý prístup dá najdôveryhodnejší výsledok?

  1. Požiadať Claude o výpočet v Chate a odpoveď manuálne prekontrolovať
  2. Nahrať premenné do Projektu a požiadať Claude o odhad hodnoty
  3. Použiť Code Execution, ktorý výpočet spustí a vráti overený výsledok
  4. Použiť Research na dohľadanie porovnateľných portfóliových scenárov z verejných zdrojov

Prečo C. Generovanie čísel ako textu môže viesť k aritmetickým chybám. Code Execution privedie Claude k tomu, aby výpočet zloženého úročenia napísal a spustil ako kód, čím vznikne presný, overený výsledok.

Q3

A legal team needs to review 500 standard vendor agreements and classify each as low, medium, or high risk based on a clear, well-defined rubric. The criteria are unambiguous and the task will run to completion in one session. Which model is most appropriate?

  1. Opus, for highest accuracy on legal content
  2. Sonnet, for balanced performance across all professional tasks
  3. Haiku, for fast and efficient structured classification at volume
  4. The default model, since model selection is not adjustable for this task type

Why C. Processing 500 documents against an unambiguous rubric calls for speed, efficiency, and consistent structured output. Haiku is built for high-volume, well-scoped classification, making it more time- and usage-efficient here than Sonnet or Opus.

Právny tím musí prejsť 500 štandardných dodávateľských zmlúv a každú klasifikovať ako nízke, stredné alebo vysoké riziko podľa jasného, dobre definovaného kritéria. Kritériá sú jednoznačné a úloha sa dokončí v jednej session. Ktorý model je najvhodnejší?

  1. Opus, pre najvyššiu presnosť na právnom obsahu
  2. Sonnet, pre vyvážený výkon vo všetkých profesionálnych úlohách
  3. Haiku, pre rýchlu a efektívnu štruktúrovanú klasifikáciu vo veľkom objeme
  4. Predvolený model, keďže pri tomto type úlohy sa výber modelu nedá meniť

Prečo C. Spracovanie 500 dokumentov podľa jednoznačného kritéria vyžaduje rýchlosť, efektivitu a konzistentný štruktúrovaný výstup. Haiku je stavaný na klasifikáciu vo veľkých objemoch s jasným zadaním, takže je tu časovo aj spotrebne efektívnejší než Sonnet či Opus.

Q4

A consultant has been working in a single Claude session for two hours on a complex analysis. In the last 30 minutes, responses have stopped reflecting the analytical framework she defined at the start. What is the most appropriate response?

  1. Increase the model tier to Opus to restore output quality
  2. Repeat the analytical framework in the current conversation to restore the context
  3. Start a new conversation, paste a summary of decisions and progress, and continue from there
  4. Enable Research to give Claude access to additional external context

Why C. This is context degradation in a long, saturated window. Continuing or re-pasting into a saturated window degrades performance further. Starting a fresh session from a summarised state clears the noise while preserving the decisions and progress that matter.

Konzultantka pracuje dve hodiny v jednej session na komplexnej analýze. Za posledných 30 minút odpovede prestali odrážať analytický rámec, ktorý na začiatku definovala. Aká je najvhodnejšia reakcia?

  1. Zvýšiť triedu modelu na Opus, aby sa obnovila kvalita výstupu
  2. Zopakovať analytický rámec v aktuálnej konverzácii a tým obnoviť kontext
  3. Začať novú konverzáciu, vložiť súhrn rozhodnutí a postupu a pokračovať odtiaľ
  4. Zapnúť Research, aby Claude získal prístup k ďalšiemu externému kontextu

Prečo C. Ide o degradáciu kontextu v dlhom, nasýtenom okne. Pokračovanie alebo opätovné vkladanie do nasýteného okna výkon ďalej zhoršuje. Nová session zo zosumarizovaného stavu odstráni šum a zachová podstatné rozhodnutia aj postup.

Q5

A consultant works on two separate client accounts and wants to ensure that context from Client A sessions does not appear in Client B sessions. What is the correct configuration?

  1. Use Incognito mode for all sessions to prevent any Memory persistence
  2. Clear Memory manually at the start of each session before switching clients
  3. Set up separate Projects for each client account and use Project-scoped Memory
  4. Use a different model tier for each client to maintain separate contexts

Why C. Projects create distinct boundaries for client data, files, and context. Keeping each client in a dedicated Project, with Project-scoped Memory, prevents context leaking between Client A and Client B.

Konzultant pracuje na dvoch oddelených klientskych účtoch a chce zabezpečiť, aby sa kontext zo sessions klienta A neobjavil v sessions klienta B. Aká je správna konfigurácia?

  1. Používať pre všetky sessions režim Incognito, aby sa do Memory nič neukladalo
  2. Na začiatku každej session pred prepnutím klienta manuálne vymazať Memory
  3. Zriadiť pre každý klientsky účet oddelený Projekt a použiť Memory na úrovni Projektu
  4. Použiť pre každého klienta inú triedu modelu, a tým udržať oddelené kontexty

Prečo C. Projekty vytvárajú zreteľné hranice pre klientske dáta, súbory a kontext. Držať každého klienta v samostatnom Projekte spolu s Memory na úrovni Projektu zabráni presakovaniu kontextu medzi klientom A a klientom B.

✓ Key
takeaways

Five things that hold across this module

  1. Select the entry point before writing the prompt

    Chat handles one-off work. Projects handle recurring work with stable context. Artifacts handle deliverable outputs. Research handles tasks requiring current multi-source information. The entry-point decision shapes every subsequent choice in the session.

  2. Four capability layers, four distinct problems

    Projects carry context. Skills define repeatable procedures. Code Execution verifies computations. Memory persists continuity. Use them independently or in combination, based on what the task requires.

  3. Model tiers reflect a speed–capability trade-off

    Haiku handles structured, high-volume tasks efficiently. Sonnet covers most professional work. Opus handles complex, high-stakes tasks where quality outranks speed. Match the tier to what the task demands.

  4. Context is a budget

    Long conversations degrade as context fills. Restart, summarise, or persist. Managing context deliberately is more efficient than working around drift after it has accumulated.

  5. Variation is inherent; review is structural

    Every Claude feature, including configured Skills, produces different outputs run to run. This module's framework determines the right entry point and capability layer. Module 3 builds the discipline to evaluate the output before it leaves your hands.

Päť vecí, ktoré platia v celom module

  1. Vstupný bod vyberte ešte pred napísaním promptu

    Chat zvláda jednorazovú prácu. Projects zvládajú opakujúcu sa prácu so stabilným kontextom. Artifacts zvládajú výstupy určené na odovzdanie. Research zvláda úlohy vyžadujúce aktuálne informácie z viacerých zdrojov. Rozhodnutie o vstupnom bode formuje každú ďalšiu voľbu v session.

  2. Štyri vrstvy schopností, štyri odlišné problémy

    Projects nesú kontext. Skills definujú opakovateľné postupy. Code Execution overuje výpočty. Memory udržiava kontinuitu. Používajte ich samostatne alebo v kombinácii podľa toho, čo úloha vyžaduje.

  3. Triedy modelov odrážajú kompromis medzi rýchlosťou a schopnosťou

    Haiku efektívne zvláda štruktúrované úlohy vo veľkom objeme. Sonnet pokrýva väčšinu profesionálnej práce. Opus zvláda komplexné úlohy s vysokým rizikom, kde kvalita prevažuje nad rýchlosťou. Priraďte triedu tomu, čo úloha vyžaduje.

  4. Kontext je rozpočet

    Dlhé konverzácie s plnením kontextu degradujú. Restart, sumarizácia alebo uloženie. Cielená práca s kontextom je efektívnejšia než obchádzanie odchýlky po tom, ako sa už nahromadila.

  5. Rozptyl je inherentný; kontrola je štrukturálna

    Každá funkcia Claude vrátane nakonfigurovaných Skills produkuje pri každom spustení iný výstup. Rámec z tohto modulu určuje správny vstupný bod a vrstvu schopností. Modul 3 buduje disciplínu, ako výstup vyhodnotiť predtým, než opustí vaše ruky.
